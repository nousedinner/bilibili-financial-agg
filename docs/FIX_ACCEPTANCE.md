## 部署与验证边界

1. **部署前备份并执行数据库升级**：`python -m scripts.manage_db upgrade`。已有 API 用户保留，不应重新生成 Key。迁移需要建表/改表权限；运行时默认 `AUTO_MIGRATE=false`，只验证结构。
2. 更新 `config.yaml` 的调度项，参考 `config/config.example.yaml`。旧 `daily_cron` 仍兼容，但原来的 21:30 配置不适合当天 22:00 截止，建议迁移为示例中的 22:10。
3. 服务使用一个 worker。首次采集之外的历史范围需调用补抓接口；自动重试默认最多 3 次，耗尽后记录保留，需排查原因再人工触发重试。
4. 旧版已经写入空摘要或空日报的数据不会仅因代码升级自动复原，需要按日期识别并重新分析后补算；本轮未执行生产历史数据修复。
5. 本地 SQLite 测试不等同于生产 MySQL 权限/DDL 验收；MySQL 命名锁及 LONGTEXT 升级尚未连接生产环境执行。
6. 未调用线上模型验收质量，未进行安卓真机 Room/DataStore、旋转/后台恢复和交互测试。测试结果不代表已经部署到线上。
