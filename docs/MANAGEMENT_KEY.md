# 管理密钥从哪里来、如何取回

管理密钥是本项目后端自己的管理口令。它用于批准发起服务器 B 站授权、检查授权及恢复指定任务等操作；B 站登录会话仍由官方扫码确认后取得。两者的来源和作用不同。

## 当前值如何确定

部署时执行 `python -m scripts.manage_db create-management-key`，程序使用 `secrets.token_urlsafe(48)` 生成一串 64 字符的随机口令。该文件存在时不覆盖，因此普通重启、升级或重新扫码不会改变这串口令。具体值由部署程序生成，没有要求项目所有者手工选择，也没有与 B 站进行密钥协商。

当前生效来源是容器内 `/app/data/management-key`，文件权限为 600。后端也支持 `FIN_AGG_MANAGEMENT_KEY` 环境变量或自定义文件路径；本次线上核对使用的是上述文件，没有环境变量覆盖。

实施时通过已配置的 SSH 读取这串口令，再通过 ADB 在自研 APP 的正常管理密钥输入框保存。正式 APP 使用 Android KeyStore 保护的 AES-GCM 本地存储保存它，并绑定服务器地址；没有读取官方 B 站 APP 的私有登录数据。

这是一种预先配置：服务器与 APP 事先保存同一个值，APP 在 HTTPS 管理请求中携带 `X-Management-Key`，服务器与保存的值比较。它没有自动协商协议，也不会替代本人在官方 B 站的扫码确认。

## 项目所有者如何查看和恢复

当前值已另行交付到本机私有文件，文件路径见本次交付消息。目录只允许当前 Windows 账号与 SYSTEM 访问，明文值没有写进仓库、测试报告或聊天正文。

也可以在已经配置 `myserver` SSH 的电脑上执行下面的命令，自行查看当前服务器保存的值：

```powershell
ssh myserver docker exec fin-agg cat /app/data/management-key
```

换手机或重新安装正式 APP 后，在“设置 → 授权与通知”保存同一个值，即可恢复管理操作权限。日常浏览和已经配置好的正常使用不需要反复填写。

当前管理密钥没有自动到期机制，不随 B 站会话到期而变化。若决定更换它，需要同时更新服务器和 APP；本次补充交付只读取现有值，没有轮换密钥、重置 APP 或改变 B 站授权。
